# Первоначальные параметры и произвольные услуги

## Пользовательский flow

В read-only режиме можно сразу указать компанию, дату, услуги, количество, сумму строки или цену единицы и НДС. Пропущенные финансовые параметры берутся только из проверенного исторического источника этой услуги у этого клиента/договора. Пример формы без привязки к клиенту:

```text
Сформируй счёт для <компания> на <дата>
Бухгалтерское обслуживание на сумму 1800 с НДС
Подготовка декларации на сумму 1000 с НДС
```

По решению владельца продукта «на сумму … с НДС» означает **сумму строки без НДС, налог сверху**. Это не цена единицы и не произвольно распределяемый итог документа. «Включая НДС»/«НДС включён» требуют уточнения суммы без налога. Явные суммы, названия и налоговые запросы пользователя имеют приоритет над образцом; история не перезаписывает их. Название строки сохраняет реально разрешённый Item_Key.

НДС берётся из подтверждённого профиля строки или явно указанного пользователем профиля/ставки, проверенного по Catalog_VATRates. Универсальной ставки по умолчанию нет. Если «с НДС» противоречит историческому освобождению/нулю, бот просит точную ставку; её можно уточнить до preview, не теряя суммы.

Количество без явного запроса берётся из образца. Если net-сумма не представима с этим количеством и ценой до 0,01, бот предлагает подтвердить количество 1 либо уточнить текстом. Молчаливого изменения количества/округления суммы нет. Обычная денежная точность, неоднозначные числовые разделители и лимиты Decimal сохраняются. Валюта берётся из договора; явно указанная валюта проверяется, конвертация не выполняется. Для первоначальных сумм валюту задают ISO-кодом.

До preview возможны выбор компании, выбор услуги, уточнение количества и исторического поставщика. Затем доступны прежние изменение/отмена/read-only проверка. После preview «Во второй строке сумма 1200» меняет net-сумму строки, а «цена 600» — net-цену единицы. Изменения одного денежного представления снимают другое, не складываются с ним. НДС/дата/название сохраняют остальные параметры.

## Разрешение услуг и источников

`resolve_service(client_id, query, selected_id=...)` работает со всеми активными Service-записями Catalog_Items. Известные bookkeeping-синонимы по-прежнему привязаны к проверенному ENV item; прочие услуги не подменяются им. Exact Description lookup — фиксированный GET с экранированным строковым литералом. Если совпадения нет, полностью читаются ограниченные name-only страницы `$top=200`, `$skip`, `$orderby=Ref_Key asc`, максимум 5000; незавершённая/нестабильная выборка закрывает поиск. Никакие entity/filter operators из пользовательского текста не исполняются.

Единственное exact-совпадение разрешается автоматически; частичные/голосовые/опечаточные совпадения и дубли дают до пяти вариантов. В UI показываются реальные коды услуг. `selected_id` поступает только из per-user token/index, действует пять минут и проверяется свежим GET по исходному запросу. Числовой ответ и исправленное название продолжают текущий выбор, сохраняя суммы/дату/прочие услуги; cancel/новое сообщение/истечение срока отзывают старую кнопку.

Для явно перечисленных услуг проверяются последние 30 posted/nondeleted invoices соответствующего клиента и договора до даты счёта (либо заданного previous_month). Каждая услуга получает свой последний однозначный источник. Источники согласуются по валюте и поставщику; если последние поставщики разные, допустим только единственный общий исторически подтверждённый поставщик, иначе требуется уточнение. Различие с Entity текущего договора сохраняет прежний supplier review и write blocker.

Повторные строки не объединяются. Явно повторённая услуга может создавать отдельные строки предложения с одной проверенной исходной строкой; это не дублирует документ 1С. Если одной сумме соответствуют несколько разных исторических строк без однозначной привязки, распределение не угадывается. При отсутствии списка услуг сохраняется совместимый bookkeeping-поиск; если такой истории нет или явно запрошен последний образец, можно использовать услуги последнего проверенного invoice. Товары не выдаются за услуги.

Нет записи/активного договора/нужной истории, неоднозначные источники, конфликт валют/поставщиков, скидки/наценки, несогласованная исходная VAT-арифметика или неизвестное финансовое значение — явный blocker, а не выдуманный default. Справочник услуг расширен, но отсутствующие данные не становятся доказанными. ItemPrices не объявлен авторитетным тарифом.

## Контракт и безопасность

- `InitialInvoiceRequest` — компактная транспортная схема новой финансовой просьбы; `LanguageIntent` остаётся схемой правок. Модель выбирает source spans, а не деньги, ставки или provider IDs. `numbers.py` декодирует значения; позиционные границы не дают перенести сумму/налог к другой услуге. Неуверенные финансовые voice-поля не применяются молча: пользователю возвращается распознанный текст для уточнения.
- `InvoiceCommand/InvoiceDraft.initial_overrides` относятся к явно перечисленным услугам. `InvoiceService.prepare` сначала получает валидный baseline, затем привязывает значения к source ID/LineNumber и повторно читает basis. После показа значения становятся обычными `preview_overrides`; начальный запрос не применяется повторно поверх последующих правок.
- `PreviewLineOverride.amount` — net-сумма, `price` — net-цена единицы; они взаимоисключающие. `ResolvedPreviewLineOverride.source_id` и `InvoiceLine.source_id`, список `HistoricalProposal.sources` фиксируют per-line происхождение. Смена источника/строки блокирует перенос правки, остальные изменения требуют обновлённого preview. BillingBasis и operation-id правило сохранены; это не долговечная write-идемпотентность.
- Дополнительно потребляется только существующий `Catalog_Items.Code` (Edm.String, проверен metadata/GET). ItemType/Description/active/ref, Invoice.Inventory, VAT/UOM/contract/entity/currency поля уже использовались. Полный metadata bundle не требуется; consumed-schema guard остаётся свежим.
- FirstBit данные не передаются AI. Все FirstBit операции — GET с dedicated reader и TLS; ONEC_WRITE_ENABLED=false. Historical/manual proposals независимо заблокированы для execute. Нет create/post/PDF, новых accounting defaults или скрытых тестовых документов.

## Проверки и навигация

`tests/test_initial_lines.py` покрывает initial precedence/fallback, разные и повторные услуги, отдельные источники, суммы/налог, источник/валюту/issuer, выбор/уточнение/отмену/чужие tokens, невозможное округление, локальный span grounding и write guard. Остальная регрессия — `tests/test_preview_overrides.py`, `tests/test_firstbit.py`, company/voice/security suite. Offline smoke: `scripts/firstbit_readonly_smoke.py`. План и фактическая live-верификация: [.agent/plans/initial-request-financial-lines.md](../../.agent/plans/initial-request-financial-lines.md).

Исторический образец может содержать цены с включённым НДС; это не меняет net-смысл явно названной пользователем цены/суммы. Точные правила пересчёта правок и округления принадлежат [PREVIEW_REVISIONS](PREVIEW_REVISIONS.md), mapping источника — [READONLY_PIPELINE](READONLY_PIPELINE.md).
